# Readable location context — November 2, 2026

Mike rejected compact ND DWR location codes as useful driver-facing descriptors and requested a city/address reference across every location kind in Dispatch and WB Tickets. No per-depot display aliases are added.

The shared pure formatter now derives a nearby Census place and approximate distance/direction for any usable ND/MT location coordinates. The reference data is the public 2026 Census Places Gazetteer:903 ND/MT internal points, bundled for offline use. The source URL, retrieval time and ZIP SHA256 are in the compact reference JSON. For example the DWR Jacob Estvold313 coordinates produce approximately7 mi E of New Town;1871 produces approximately4 mi N. These are calculated examples, not hardcoded exceptions. All such references say straight-line, never a road distance or postal address. Verified stored address/city values take precedence. Invalid/zero/out-of-region coordinates do not invent a town. No network geocoding, paid API, live catalog rewrite or customer data import is introduced. The calculator never writes/replaces the selected site's GPS or changes map routing.

Nearby-town context replaces the compact survey code in search rows when available. The existing depot detail card retains the survey but expands ND's compact TTT/RRR/SS/tract code into Sec/Township/Range/Tract words. Already-readable NDIC/MT legal strings stay intact. County and source identity remain. Result keys, selection, dedup and all other T303 behaviors are preserved.

TypeScript passes in both repositories. Device/live release evidence is recorded separately; T303 remains the installed baseline until the new package is verified.
